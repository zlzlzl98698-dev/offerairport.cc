## 直接结论：99% 日常时间锁定 Rule（规则模式），仅在冷门漏判与排障时临时切换 Global

在 Clash Verge Rev、FlClash、Clash Nyanpasu 以及移动端的 Stash 主界面顶部（或「代理」页顶端），最醒目的三个核心开关就是 **`Rule（规则）`**、**`Global（全局）`** 与 **`Direct（直连）`**。许多新手第一次上手时有个极容易误解的直觉：“规则模式好像只管一部分，全局模式把所有网络全接管，那开全局肯定更稳更彻底吧？”

事实恰恰相反。**在中文互联网与海外日常高频混合使用的环境下，长期挂在 Global 全局模式反而是拖慢网速、烧光套餐流量甚至引发国内账户风控的头号元凶。**

| 模式名称 | 中文界面显示 | 流量调度路由逻辑 | `AI / 流媒体` 独立策略组是否生效 | 适用场景建议 |
| :--- | :--- | :--- | :--- | :--- |
| **Rule** | **规则模式** | 逐条比对 `rules`：国内域名/IP/局域网走 `DIRECT`，海外走代理组，广告拦截走 `REJECT` | **完全生效**（如自动让 ChatGPT 走美国、日常网页走香港） | **日常 99% 时间绝对首选默认锁定** |
| **Global** | **全局模式** | 跳过所有分流规则，**除了局域网回环外，海内外所有流量全部塞入 `GLOBAL` 策略组** | **失效**（统一被迫按你在 `GLOBAL` 里挑的单一节点走） | 仅限排查“冷门小众海外站是否漏网”或单节点诊断，用完即切回 |
| **Direct** | **直连模式** | 全部连接请求直接由本地物理网卡直出，不经过任何远程代理节点 | 不走代理 | 需要短暂直连测速、连内网工具而不愿退出软件时使用 |

## 一、为什么绝对不能把 Global 全局模式当成日常主力？

从实际消耗、物理路由和风控机制三个维度看，长期开着全局模式都会直接损害你的体验：

### 1. 绕路延迟暴涨，国内软件反受其害
假设你住在杭州或北京，想打开百度网盘、看一场国内高清直播或者用微信小程序处理工作。直连物理链路本来只有几毫秒至十几毫秒；一旦开了 `Global` 模式并指向了一条日本或美国节点，这笔请求就变成“**国内宽带 → 跨境专线 → 东京/洛杉矶节点服务器 → 再跨越太平洋绕回北京/杭州机房**”，不但延迟瞬间飙升上百毫秒，还白白受限于中转节点单端口瓶颈。

### 2. 白白烧光你的月度高速流量配额
绝大多数高性价比机场按月限制总流量（常见为 `100GB–168GB/月` 档位，详情可见 [主流机场真实流量档位对照](/airport/#core-candidates-table)）。国内刷一小时 4K 电视剧、或者后台微信电脑版自动同步工作群几百 MB 视频文件、Steam 下载几个大更新，如果在全局模式下全部经海外代理转发，一个晚上就能直接把你一整月的配额耗尽断网；更别提不少节点在转发非本地内容时还可能触发倍率扣费。

### 3. 摧毁订阅内置的“精细地区分流”与 AI 保护
优质订阅与自定义配置（如 [Clash Verge 规则与策略组配置](/clash/verge-rules-and-proxy-groups/)）往往精心把不同服务拆到了独立通道：香港低延迟专线看 YouTube/Google，日本/新加坡/美国固定干净节点跑 ChatGPT 与 Claude，台湾节点看特定地区版权剧。然而一旦切换成 `Global`，所有的子策略组全部失效，整个系统退化成“一锅炖全走一条节点”——选香港则打不开 ChatGPT，选美国则看本地网页又偏慢。

### 4. 国内网银与生活 App 异地风控拦截
许多国内金融 App、证券软件、公司钉钉打卡以及支付风控系统在检测到用户的公网出口 IP 突然跳到了新加坡或美国数据中心时，会立刻弹出短信人脸二次验证甚至触发临时安全锁。保持 `Rule` 模式让全部国内服务直出，就能彻底避免这种无妄之灾。

## 二、什么时候才应该临时切换 Global 或 Direct？

当然，软件既然保留了另外两个开关，就代表它们各自存在不可替代的诊断价值：

### 情景 A：需要临时切到 **`Global`（全局模式）** 的两大场景
1. **排查极冷门海外科研网站或小众论坛被漏判直连**：由于任何一份 GeoSite 规则集都不可能 100% 收录全世界的几亿个小众域名，偶尔遇到一个刚上线不久的国外学术站点或冷门开发文档库在 Rule 模式下一直转圈打不开时，先临时点一下 `Global`（记得同时去 **`GLOBAL` 策略组**选一个可用海外节点！）刷新该网页——如果一瞬间秒开，说明节点没问题，只是这个域名漏进了 `MATCH` 直连或规则错误判断成了国内直出。验证完毕后，直接把该域名写进你的扩展覆写前置直连/代理规则里，然后马上切回 `Rule`！
2. **排除“损坏的分流规则”导致的玄学断网**：当你导入了一套不知从哪里抄来的复杂第三方配置文件，发现连 Google 都连不上时，临时切 `Global` 选一个确定亮绿字的节点做对照。如果全局通了而规则不通，说明错误出在配置的 `rules` 与 DNS 分流段里。

### 情景 B：需要临时切到 **`Direct`（直连模式）** 的三大场景
1. 电脑需要运行纯本地测试（如测真实宽带测速、本地局域网开发服务抓包），想暂时停掉转发又不想彻底关掉 Clash 托盘；
2. 电脑打开着系统代理，临时要登录绑定公司固定 IP 白名单才能进入的政务或企业内部网站；
3. 准备单独对比开启代理前后的网页加载耗差。*(注：若在玩竞技游戏且打算开启合规网游加速器，切 `Direct` 如果仍保留着 Clash 的 TUN 虚拟网卡驱动接管，依然可能和加速器冲突，此时仍推荐直接在客户端关掉 TUN 开关后再用加速器，详见 [游戏加速器与代理路由冲突解析](/guides/game-booster-vs-proxy/)。)*

## 三、切完模式如何 10 秒核实流量到底走没走对？

千万不要靠体感瞎猜！任何时候只要不确定某个网站当前到底走了本地还是走了香港/美国节点，按这三步就能拿到 100% 实锤证据：

1. 打开 Clash Verge Rev 左侧导航栏的 **「连接（Connections）」** 界面；
2. 在顶部的搜索过滤框里直接输入目标网站域名关键词（例如 `taobao` 或 `openai` 或 `github`）；
3. 刷新目标网页，观察立刻新跳出来的连接条目右侧两列标签：**「规则（Rule）」与「链路（Chains）」**——
   - 若访问国内网银或下载国内文件时看到链路列显示 **`DIRECT`**，说明分流完全健康、零浪费；
   - 若发现本该直连的大型下载竟然走在了海外节点链路名上，或者切 Global 却看到链路停在 `DIRECT` 而不是海外节点，立刻根据命中规则条数调整对应策略组选择即可。若全部链接显示异常或超时，可进一步参照 [Clash 节点超时排查九步法](/clash/fix-node-timeout-errors/) 与 [Clash DNS 防泄漏配置指南](/clash/dns-fakeip-configuration-guide/) 逐层排障。
