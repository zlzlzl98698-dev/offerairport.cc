## 直接结论：始终优先采用「手动复制订阅 URL 导入」并核对协议格式

拿到服务商的订阅链接后，很多新手习惯在网页后台直接点击「一键导入到 Clash」。虽然一键导入在理想环境下可以自动唤起桌面客户端，但受限于不同浏览器的安全弹窗拦截、多版本 Clash 遗留注册表冲突以及系统协议绑定异常，一键呼起经常出现点击无反应或报错的情况。

**工程上最稳妥、跨系统 100% 通用的导入方式，是在服务商后台点击「复制 Clash 订阅链接」（以 `https://` 开头的完整 URL），粘贴到 Clash Verge Rev 的「订阅（Profiles）」顶部输入框点击导入，然后左键单击新生成的卡片将其激活。**

开始导入之前，先花 10 秒确认两个前提条件：
1. **你的服务商支持第三方通用客户端**：正如《第三方代理客户端》资料所区分的，机场软件分为 **第三方通用客户端**（如 Clash Verge Rev、v2rayN、Shadowrocket、FlClash、Hiddify）和 **机场专属客户端**。如果某品牌只提供账号密码登录的封闭专用软件而根本不提供订阅链接，则无法直接导入 Clash Verge Rev，相关风险与差异可参阅 [专属客户端 vs 第三方通用客户端对比](/comparisons/custom-app-vs-universal-client/) 与 [封闭专属客户端潜在风险解析](/resources/proprietary-client-risks/)。
2. **订阅当前处于可直连状态（或你已有可用节点）**：导入动作本质上是让 Clash Verge Rev 向服务商面板的服务器发起一次 HTTP GET 请求并下载 YAML 文本。

## 一、导入前置判断：订阅格式识别与兼容性对照

不同服务商的用户面板提供的订阅链接格式并不统一，直接把非 Clash 格式的链接塞进 Clash Verge Rev 是造成「Yaml 解析失败（Invalid YAML）」或「导入后节点列表为空」的首要原因。导入前请先对照下表识别手头的链接格式：

| 后台按钮常见命名 | 实际返回的数据格式 | Clash Verge Rev 能否直接导入 | 不支持时的正确处理方式 |
| :--- | :--- | :--- | :--- |
| **Clash / Clash Meta / Mihomo** | 标准 YAML 配置文件（含 `proxies`、`proxy-groups`、`rules`） | **原生直接支持（首选）** | 直接复制链接粘贴导入即可 |
| **通用订阅 / V2Ray / v2rayNG** | Base64 编码的纯节点 URI 文本（`vmess://`、`vless://` 等） | **不能直接当完整配置导入** | 需进行格式转换或使用 `Sub-Store` 转换为 Clash YAML |
| **Shadowrocket（小火箭）** | Base64 节点列表或带简单参数的列表 | **部分无法直接识别策略组** | 优先改复制面板中的 Clash 链接，或做格式转换 |
| **sing-box / SFI / SFA** | 原生 JSON 配置文件 | **不兼容 YAML 引擎** | 如只有 sing-box 格式，改用 Karing / Hiddify / v2rayN 或转换格式 |

如果你确认服务商后台**只提供了通用 Base64 订阅或 V2Ray 链接**，切勿在导入报错后反复重试。请先阅读 [订阅格式转换与兼容性处理指南](/clash/subscription-format-conversion/)，或按 [Sub-Store 本地化安全部署教程](/clash/sub-store-local-deployment/) 在本机完成安全转换，切忌随意将私密订阅地址提交给来路不明的第三方在线转换接口。

## 二、标准导入 4 步全流程（含一键导入失效补救）

### 第 1 步：准备干净的本地网络环境

在粘贴新订阅之前，确认桌面左下角或「设置」页面中的 **「系统代理（System Proxy）」和「TUN 模式」均处于关闭状态**（除非你当前需要借助另一个已连通的备用节点去拉取被屏蔽的订阅域名）。如果不小心开着已过期的旧节点系统代理去导入新订阅，请求会被送进死节点里并直接报超时错误。

### 第 2 步：在 Clash Verge Rev 中导入并「激活」配置

1. 打开 Clash Verge Rev，点击左侧菜单 **「订阅（Profiles）」**。
2. 将从面板复制好的 `https://...` 订阅 URL 粘贴至顶部的长条输入框中，不要前后多带空格或中文汉字。
3. 点击输入框右侧的 **「导入（Import）」** 按钮，等待 1–3 秒。
4. 导入成功后，下方会出现一张写有订阅名称、流量进度条与到期时间的卡片。
5. **关键一步（新手极易遗漏）**：用鼠标**左键点击一次这张新建卡片**，让卡片边框呈现高亮激活样式。如果只点导入而不左键单击激活，内核依然加载着空白或旧配置，切到「代理」页面会发现依然看不到任何新节点。

### 第 3 步：设置自动定时更新与代理更新策略

机场的入口中转服务器 IP、端口以及防封锁域名会随网络线路维护动态调整。长期不更新订阅，原本流畅的节点过几周就会莫名其妙全部变成 Timeout。

在已激活的订阅卡片右上角点击菜单按钮（或**鼠标右键点击卡片 → 编辑信息 / Edit Info**），按以下标准配置参数：

- **名称（Name）**：可修改为便于辨识的备注（如「主用订阅」「备用线路」）。
- **更新间隔（Update Interval）**：单位为分钟，推荐填写 **`720`**（每 12 小时自动更新一次）或 **`1440`**（每 24 小时一次）。尽量不要填写低于 `60` 分钟的数值，频繁请求既容易触发面板限流，也会在后台更新瞬间重置当前手动选定的节点连接。
- **使用系统代理更新（Use System Proxy）**：
  - 当服务商使用了**国内可直连的订阅专用域名**时，保持**关闭**，让软件直连更新最稳妥。
  - 只有当订阅域名本身被屏蔽、直连必失败时，才在「自己已经连上可用节点」的前提下勾选通过代理更新；但要注意一旦所有节点彻底失效，必须临时取消勾选再配合新域名更新，否则会陷入死循环。
- **仅在启动时更新 / User-Agent**：新版 Mihomo 协议（如 VLESS-Reality、Hysteria2）节点有时依赖服务端根据客户端 `User-Agent` 判断下发标准 Clash 还是 Clash.Meta 配置。Clash Verge Rev 默认的 UA 能够正常识别，若遇到面板只下发了旧版 SS 节点而缺少新协议节点，检查配置里的 `User-Agent` 是否被改写成了旧版 `ClashForWindows`。

### 第 4 步：本地 YAML 文件拖拽导入（离线应急场景）

当某些特殊网络环境完全阻断了订阅 URL 拉取，且你已经通过手机或网页端直接把 `.yaml` 配置文件下载到了本地硬盘时，可以直接在电脑上用鼠标将该 `.yaml` 文件拖入 Clash Verge Rev 的「订阅」页面空白区域，或者点击右上角的本地文件导入按钮选择导入。注意本地文件导入后**没有远程 URL，无法自动更新**，后续恢复直连后记得重新导入在线 URL 卡片。

## 三、用命令行快速诊断订阅链接是否真正可用

当你在软件里点击「导入」或「刷新」却反复弹出红色报错提示，不知道是软件问题还是服务商订阅地址本身挂了时，可以先**在关闭系统代理的情况下**，用系统终端向订阅链接发起一次模拟请求，3 秒就能分清责任边界：

```powershell
# Windows PowerShell 模拟 Clash 请求头测试订阅链接返回状态（请替换为你的实际订阅链接）
Invoke-WebRequest -Uri "你的订阅URL" -Headers @{"User-Agent"="clash-verge/v2.0"} -Method Get | Select-Object StatusCode, @{N='Size';E={$_.Content.Length}}
```

```bash
# macOS / Linux 使用 curl 测试 HTTP 状态码与返回大小
curl -I -A "clash-verge/v2.0" "你的订阅URL"
```

根据返回的状态码判断故障根源：
- **返回 `HTTP 200` 且返回内容非 HTML 登录页**：说明订阅服务本身完全正常，问题出在 Clash Verge Rev 的本地 YAML 解析、覆写规则冲突或代理更新死循环。
- **返回 `HTTP 403` / `401` / `404`**：说明你的订阅 Token 已被重置、账号已到期被面板拦截，或订阅域名已更换，需登录服务商后台重新复制新链接。
- **终端直接报 `Could not resolve host` 或 `Timed out`**：说明当前宽带无法直连该订阅域名（DNS 污染或被屏蔽），需询问服务商获取备用防失联订阅地址，或切换手机热点后完成更新。

如果遇到更复杂的报错代码（如 `429`、`502` 或 TLS 握手错误），请直接对照 [Clash Verge 订阅更新失败报错解决大全](/clash/fix-subscription-update-failed/) 排查。

## 四、切换节点、策略组逻辑与测速正确打开方式

成功激活订阅卡片后，切换到左侧 **「代理（Proxies）」** 页面完成上线前最后三步校验。

### 1. 确认顶部模式为「规则（Rule）」

除非你在进行特定的全局调试，否则顶部永远选择 **规则（Rule）**，详细对比可见 [规则模式、全局模式与直连模式实战区别](/clash/rule-vs-global-mode/)。

### 2. 看懂常见策略组类型图标与含义

服务商下发的配置通常包含多层策略组，理解每种分组的机制可以避免「明明选了日本节点却还是走香港」的困惑：

| 策略组类型（YAML Type） | 工作机制 | 日常使用建议 |
| :--- | :--- | :--- |
| **`select`（手动选择）** | 由用户手动点击决定固定走哪一个节点或子策略组 | 主力选择组，适合固定地区（如锁定日本或新加坡看流媒体/用 AI） |
| **`url-test`（自动测速）** | 内核按周期向测速 URL 发请求，自动切到延迟最低的节点 | 适合懒人日常浏览，但不适合要求 IP 稳定不变的账号登录与支付场景 |
| **`fallback`（故障转移）** | 优先使用排在第一位的节点，只有当它超时不可用时才按顺序自动往下切换 | 兼顾稳定性与高可用，适合主备多线路容灾 |
| **`load-balance`（负载均衡）** | 将不同请求按轮询或哈希分散到多个节点发出 | 一般仅用于大并发爬虫或下载场景，普通网页登录易触发风控，慎选 |

### 3. 执行延迟测速与合理判读结果

点击策略组右侧的 **闪电图标**（注意与单节点右侧点击单测区分），客户端会在几秒内通过内网测速 URL（默认为 `http://www.gstatic.com/generate_204`，可在「设置」中自定义为 `http://cp.cloudflare.com/generate_204`）完成全组探测：

- **绿色数值（`< 150ms`）**：多见于香港、台湾、日本、新加坡等周边地区节点，网页秒开响应良好。
- **橙色数值（`150ms–350ms`）**：多见于美国、欧洲等远距离物理节点，正常合规延时，日常使用依然流畅。
- **显示 `Timeout`**：说明当前节点对该测速接口握手超时。如果**个别节点**显示 Timeout，跳过改选绿色节点即可；如果**整组全部节点**都显示 Timeout，先别怀疑机场跑路，立刻按 [Clash 节点全部 Timeout 超时 9 步排查](/clash/fix-node-timeout-errors/) 检查系统时间与端口占用。

需要再次强调的是：**延迟低不代表实际跑满带宽速度一定快**。想真实评估节点的 4K 吞吐量、晚高峰抗丢包能力与流媒体/AI 解锁成色，请参照 [节点测速方法论与真实速度验证](/resources/#node-testing-guide) 与 [如何科学测试节点真实速度与解锁](/resources/how-to-test-nodes/)。

### 4. 开启「系统代理」并完成连通性双端验证

回到 **「设置（Settings）」**（或主界面左下角快捷开关），打开 **「系统代理（System Proxy）」**。随后在浏览器打开两个页面做双端交叉验证：
1. 访问海外目标站点（例如 `https://www.google.com` 或 `https://github.com`）确认能快速渲染加载。
2. 访问国内常去站点（例如 `https://www.baidu.com` 或本地测速页面）确认归属地仍是本地宽带 IP 且保持高速直连，未被错误全局代理绕行。

## 五、流量进度读取机制与「流量异常缩水」排查

Clash Verge Rev 订阅卡片上显示的「已用流量 / 总流量」与「到期日期」，并非软件自己计算的本机网卡统计，而是通过读取服务商面板 HTTP 响应头中的 **`subscription-userinfo`** 字段（包含 `upload`、`download`、`total`、`expire` 四个字节数与时间戳参数）直接解析展示出来的。

在实际运维中，常出现两类关于流量读数的疑问：

1. **刚在网站续费或购买了重置包，客户端进度条却没变化**：客户端不会每秒轮询服务端接口，必须前往「订阅」页面点击卡片右上角的 **「刷新（圆圈箭头）」** 按钮手动拉取一次响应头，数值才会同步更新。
2. **晚上没怎么看视频，流量统计却莫名其妙掉了几十 GB**：可能的原因有三种——其一是部分高成本专线或 AI 节点带有 `1.5x`、`2x`、`3x` 的**倍率计费系数**；其二是软件配置了 `Global` 模式导致百度网盘、Steam 游戏更新、Windows 系统更新或 BT 下载全部走了代理节点；其三是订阅链接在外部环境泄露被他人盗刷。排查方法可对照 [机场流量消耗异常或疑似泄漏排查指南](/resources/subscription-traffic-leak-fix/) 逐一核实，如确认疑似泄露，第一时间去服务商后台点击「重置订阅链接（Reset UUID / Token）」，再把新链接重新导入客户端。

## 六、安全操作红线与延伸学习路径

在订阅管理环节，请始终牢记三条安全红线：
- **不要把订阅链接直接发到任何公开群聊或截图露出来**，URL 末尾的 Token 参数一旦暴露，任何人都可以直接导入并消费你的套餐流量。
- **不要使用来路不明的在线订阅转换页面**，确实需要转换格式时坚持使用本地部署或可信开源方案。
- **不要随意在浏览器登录面板时保存密码在公共电脑上**，同时定期核查订阅是否开启了可信间隔更新，具体安全与订阅流程总规范亦可回顾 [Clash 订阅工作流总纲](/clash/#subscription-workflow)。
