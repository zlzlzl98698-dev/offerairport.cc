## 核心结论：除非你明确知道节点与本地路由均完整支持 IPv6 代理，否则在 Clash DNS 中关闭 `ipv6: false`

近年来三大运营商家庭宽带与高校校园网已全面普及原生长前缀 IPv6 地址（`240e` 电信、`2408` 联通、`2409` 移动/教育网）。在直连访问国内各大网站和网盘时，IPv6 确实带来了充沛的地址空间；可是一旦你在路由器或设备上开启科学上网代理，这张好心下发的原生 IPv6 网络却极易变成让网页 **「转圈 10 秒才打开」「时而连上时而全断」「检测页直接暴露中国本地真实归属地」** 的最大暗坑。

搞懂操作系统与浏览器面对双栈地址的 **「Happy Eyeballs 优先回退僵持期」** 以及代理客户端接管盲区，只需三分钟修改两项配置，就能让卡成慢动作的网页加载立刻恢复秒开爽感。

本问题常与 DNS 污染和 WebRTC 泄露伴随出现，可同步参阅 [Clash DNS Fake-IP 配置模板](/clash/dns-fakeip-configuration-guide/) 与 [WebRTC 与 DNS 泄漏堵漏指南](/guides/webrtc-and-timezone-leak-prevention/)。

## 一、底层成因拆解：为什么「原生 IPv6 + 普通代理」会变成卡顿与泄漏重灾区？

当你的家庭宽带下发了公网 IPv6，而大部分市面上稳定高速的中转与 IEPL 机场专线隧道主要仅构建和转发 IPv4（或者你用的配置文件未妥善声明接管 IPv6 路由表）时，浏览器发出一声访问 `google.com` 或 `youtube.com` 的请求后，后台究竟经历了什么灾难现场？

| 双栈冲突具体场景 | 发生机制解析 | 用户眼睛看到的表面现象 |
| :--- | :--- | :--- |
| **场景 1：直连竞速死等超时** | 操作系统同时查到了海外网站的 IPv4 (`A`) 和 IPv6 (`AAAA`) 地址，并按现代系统「IPv6 优先」规则，绕过只管 IPv4 的代理尝试拿本地公网 IPv6 去直连谷歌 | **每次打开新外网域名必定先空白转圈 8–15 秒**，超时失败回退后才突然加载出来 |
| **场景 2：支持访问的外网悄悄「穿帮」直连** | 访问某些海外未受阻挡但极度在意风控地区的检测站、流媒体 CDN 或跨境后台时，IPv6 数据包顺顺当当绕过代理直接用家里宽带飞了出去 | `ipleak.net` 里 IPv4 显示美国，**IPv6 赫然爆出自己本地省市的电信/移动宽带公网地址** |
| **场景 3：校园网 IPv6 计费/规则混乱** | 部分高校对校内 IPv4 限制认证且独立计费，而教育网 IPv6 通道另行放行却受限于代理策略无法精准匹配分流 | 一开校园网就莫名消耗计费流量，或者在开着 TUN 模式时连校园内网认证首页也打不开 |

## 二、3 步实操：彻底治理 Clash Verge Rev、移动端与软路由的 IPv6 冲突

根据你所处设备类型，按下面针对性的稳妥方式关闭多余代理侧 IPv6 干扰即可立竿见影：

### 1. 桌面端 Clash Verge Rev / Mihomo（最常见解法）

哪怕上游机场发下来的 YAML 订阅自己把 `ipv6` 打开了，我们一样可以用本地「全局扩展配置」一刀锁死并防止订阅更新后失效：

1. 打开 **Clash Verge Rev** 左侧 **「设置 (Settings)」 → 「Clash 内核设置」**，先检查界面中的 **「IPv6」** 主开关，确认其处于 **关闭（灰色）** 状态。
2. 为了确保某些机场订阅正文里自配的 `dns.ipv6: true` 不会绕开界面开关继续下发 AAAA 假地址，进入左侧 **「订阅 (Profiles)」**，找到你当前启用的配置或设置全局扩展覆写文件（Merge），检查并加入下方精简段：

```yaml
ipv6: false
dns:
  ipv6: false
```

3. 如果你的桌面电脑正在开启 **TUN 虚拟网卡模式** 且本机依然拿到公网 IPv6，建议同时核查全局 `tun` 段下的 `route-exclude-address` 是否无意冲突，或在本地配合 [Fake-IP 完整干净配置模板](/clash/dns-fakeip-configuration-guide/) 使用，把所有国外解析收归由 `Fake-IP` 下发干净的 `198.18.x.x` 虚拟 IPv4 池（浏览器一收到 Fake-IP 就再也不会傻等任何 AAAA IPv6 记录了！）。

### 2. iOS / Android 手机端（Shadowrocket、FlClash、v2rayNG）

手机切到 5G 移动数据时，三大运营商几乎 100% 下发原生 IPv6，手机端网页卡顿往往比电脑端还要严重：
- **Shadowrocket（小火箭）**：点击底栏 **「配置」** 进入正在使用的配置编辑页 → 点击「通用」，确认 **「IPv6 支持」处于关闭（关闭状态下对代理规则域名返回空 AAAA）**，如有异常并顺带确认关闭不需要的复杂系统拦截干扰。
- **FlClash / v2rayNG**：在软件「设置 → 网络 / 核心参数」中寻找 **「启用 IPv6（Enable IPv6）」** 或 **「优先 IPv4 / 禁用绕行」** 相关选项并设为关闭（或在 v2rayNG 的域名解析策略里改为 `UseIPv4` / `AsIs` 视分流规则配合）。

### 3. OpenWrt 家庭软路由（OpenClash / Nikki / PassWall2）

家里有软路由接入全家苹果电视、游戏机、手机时，路由器一旦把局域网 IPv6 通告发给内网所有终端，哪怕路由器上的代理插件没处理好都会全员一起泄漏转圈：
- **在 OpenClash 中**：进入「插件设置 → DNS 设置 / 常规设置」，确保 **「IPv6 流量代理」** 在不需要纯双栈场景时关闭，并勾选对应的 **「禁止解析 IPv6 DNS（仅 IPv4 响应 / 过滤 AAAA）」** 类选项（具体菜单随版本命名微调）。
- **彻底省事做法（内网无特殊 IPv6 刚需家庭）**：直接在 OpenWrt「网络 → 接口 → LAN（以及 WAN6）」中停用对内网设备的 IPv6 路由器通告（RA / DHCPv6），全家内网干净统一跑 IPv4 并交由软路由插件分流，多设备稳定性立升一档。

## 三、改完之后的双项自检验收标准

配置完成并重启客户端/重载配置后，花 1 分钟按以下顺序验收：

1. **访问测试页验证零泄露**：打开 `test-ipv6.com` 或 `ipleak.net`，确认界面不会直接印出中国本地 `2408/2409/240e` 宽带 IPv6，只清晰呈现节点出口归属。
2. **体验高密度海外网页起手速度**：在浏览器的无痕窗口顺次点开 `google.com`、`github.com`、`youtube.com` 与 `chatgpt.com`，观察地址栏点击回车后是否 **在 0.5 秒内即开始渲染响应**，彻底告别以前那种「前 10 秒死寂白屏、后面突然一下子刷出来」的粘滞感。
3. **检查国内网盘/微信/视频是否依然直连**：开着 `Rule`（规则）模式试一下国内常访网页和下载，确认没有因为关掉了代理通道的 IPv6 而导致国内直连失灵（若连带出现异常，务必去 Windows 防火墙和 Chrome 安全 DNS 里排查是否错关了全局设置，参考 [Windows 网络重置与排查指南](/clash/windows-firewall-and-uwp-loopback/)）。
