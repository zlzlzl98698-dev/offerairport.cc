## 核心结论：排查顺序为「关闭浏览器自带 DoH → 修复 IPv6 绕行 → 限制 WebRTC 暴露本地接口 → 按需对齐系统时区」

不少用户在做海外业务注册、接入特定地区 AI 平台，或者单纯跑了一遍 `ipleak.net`、`whoer.net` 这类网络检测站时，往往会惊出一身冷汗：**「我电脑明明开了 Clash 代理、IP 显示也在东京或洛杉矶，为什么检测页面下面的 DNS 栏里赫然列出了一排中国电信/联通的服务器，甚至直接弹出了我本地宽带的公网 IPv6 地址，风控分直接亮红灯？」**

出现这种「穿帮」现象，几乎从来不是你的机场节点失效了，而是浏览器的四层底层机制绕开了代理网关：**浏览器独立 DoH 解析绕行、IPv6 双栈直连泄漏、WebRTC P2P STUN 探测，以及浏览器与系统暴露的 `UTC+8` 时区语言指纹。** 按以下四个固定排查阶梯逐一堵死漏洞，10 分钟就能把日常与涉外环境的检测隐蔽性拉平。

如需顺带核验当前节点落地 IP 是否处于各大平台黑名单或机房标记库，请联合查看 [IP 纯净度评估与流媒体/AI 解锁自检教程](/resources/ip-purity-and-unlock-check/) 与 [VPN 与代理隐私泄漏专题解答](/vpn/#dns-webrtc-leaks)。

## 一、四维穿帮漏洞速查诊断表

| 泄漏层类型 | 典型检测表现现象 | 根本技术原因 | 普通用户是否必须解决 |
| :--- | :--- | :--- | :--- |
| **1. DNS 解析泄漏** | 出口 IP 显示海外，但检测页 DNS 列表中出现了国内三大运营商本地节点 | 只开系统代理未接管系统 DNS、或者浏览器自开了安全 DNS 绕开 Clash Fake-IP | **强烈建议修复**（既防隐私暴露又大幅加快网页打开速度） |
| **2. IPv6 绕行泄漏** | 网站或检测页直接爆出本地宽带真实的 `2408/2409/240e` 开头 IPv6 地址，或访问 Google 卡死 | 本地宽带已分配原生公网 IPv6，但代理节点或客户端配置没接管 IPv6 转发 | **必须排查处理**（极高概率导致国内直连泄漏甚至外网打不开） |
| **3. WebRTC 接口暴露** | 隐藏在检测页面的 WebRTC 一栏泄露了内网私网段（如 `192.168.x.x`）甚至穿透出了真实公网 IP | Chrome/Firefox 默认允许网页 JS 调用 STUN 服务器探测真实底层网卡 | 日常刷剧无妨；**跨境风控账号、严格地域校验平台必封堵** |
| **4. 时区与系统语言指纹** | IP 是美国洛杉矶，但浏览器向 JS 汇报系统时区为 `Asia/Shanghai (UTC+8)` 且语言为 `zh-CN` | 海外节点 + 中国本地操作系统未隔离时区与地区配置 | 仅高敏跨境店铺、广告户及运营业务环境需要统一伪装对齐 |

## 二、逐层实战堵漏：4 步消除泄漏隐患

### 第一步：堵死 DNS 泄漏（让所有域名解析统一走代理防污染链路）

DNS 泄漏是导致访问海外域名卡顿甚至被识别地理位置异常的头号元凶，修复遵循「客户端接管 + 浏览器让路」原则：

1. **在客户端启用成熟的 Fake-IP 与安全 DNS 模板**：如果你用的是 Clash Verge Rev（Mihomo 内核），确保开启 **Fake-IP** 增强模式并将国外域名解析分配给可靠的加密远端服务器（详见 [Clash DNS Fake-IP 防泄漏完整模板](/clash/dns-fakeip-configuration-guide/)）；同时**推荐开启 TUN 虚拟网卡模式**，接管掉浏览器之外的系统级异步 UDP 53 解析。
2. **关闭浏览器自带的「使用安全 DNS（DoH）」**：
   - **Chrome**：打开「设置 → 隐私和安全 → 安全 → 进阶」，**关闭「使用安全 DNS」** 开关（防止浏览器跳过系统代理，擅自去用内置的预设服务器直接发起解析而产生地域穿帮或连不上）。
   - **Edge**：同样在「设置 → 隐私、搜索和服务 → 安全性」中关闭「使用安全 DNS 指定如何查找网站的网络地址」。
3. **验证方法**：打开 `ipleak.net` 或 `dnsleaktest.com` 运行标准测试，观察返回的 DNS 列表——如果全部只显示你当前选中的代理地区服务器（或你指定的海外加密 DoH 节点，例如日本/美国 Cloudflare/Google 节点），完全不见国内 IP，即说明 DNS 堵漏成功。

### 第二步：修复原生 IPv6 绕行冲突（杜绝真实归属地秒露）

由于我国宽带和手机 5G 已普遍大规模下发原生 IPv6，一旦你的本地网卡拿到公网 `240e/2409` 前缀，而大多数中低价机场隧道默认只针对 IPv4 做转发，浏览器向支持双栈的海外网站发起连接时就会顺手走了「IPv6 直连通道」，直接把你真实国内归属地甚至省市暴露得一干二净。

- **标准处置**：在 Clash / Mihomo 配置文件的 `dns:` 与入口配置中明确关闭 IPv6 解析与转发（如设置 `ipv6: false`），并在需要极端防漏的场景核对是否暂时在客户端/系统路由中屏蔽未经代理接管的海外 IPv6 出口。具体排查指令和冲突示例请参照 [双栈 IPv6 冲突与断网泄漏修复全书](/resources/ipv6-conflict-and-dual-stack-fix/)。

### 第三步：精准隔离 WebRTC，防止真实网卡地址穿透探测

WebRTC（网页实时通信）为了建立点对点音视频通话，默认允许网页脚本向外部 STUN 服务器发送探测包并拿回你的真实网络接口地址，这一探测有时能绕过传统的 HTTP 系统代理端口！

- **Chrome / Edge 用户（最稳妥做法——建立独立环境 Profile + 限域策略）**：
  - 不建议把日常登录国内银行和开腾讯会议的主配置搞坏。最优雅的做法是在 Chrome 右上角头像处**新建一个专门用于跨境访问的独立用户配置（Profile）**。
  - 在这个独立 Profile 下，安装口碑良好的开源隐私控制扩展（如 **`uBlock Origin` 内置设置开启「阻止通过 WebRTC 泄露本地 IP 地址（Prevent WebRTC from leaking local IP addresses）」**，或使用轻量化权限最小的 WebRTC 策略扩展将其模式锁死为 **`Disable non-proxied UDP`**，意为禁止不走代理端口的一切 UDP 穿透请求，从而既堵死真实 IP 泄漏又不完全掐死经由代理的正常连接）。
- **Firefox 用户（无需任何插件，原生内核级开关）**：
  - 在地址栏输入 `about:config` 回车确认提示 → 搜索 **`media.peerconnection.enabled`** → 双击将其改为 **`false`**（仅限纯匿名高隐蔽窗口或专门配置的容器 Profile 中开启）。

### 第四步：按需控制时区、语言与浏览器指纹（仅高敏跨境业务关注）

对普通科研查阅资料和看流媒体来说，前面三步做好后就已经处于极高的网络健康状态了。唯独如果你运行的是跨境独立站后台收款、TikTok 矩阵账号或严格风控电商运营，前端 JavaScript 还会顺手读取系统 API 中的 `Intl.DateTimeFormat().resolvedOptions().timeZone` 和 `navigator.language`：

- 一边连着日本东京或美国得州的节点，一边向站点汇报电脑时间是 `UTC+8 (Beijing/Shanghai)`、系统默认中文语言包，哪怕 IP 再干净也极其容易触发人工审核甚至秒封。
- 此类生产环境务必配合独立的指纹浏览器或专用隔离环境容器调整系统时区与语言，切勿直接拿着日常混用国内网盘和微信的主力日常浏览器直接硬闯高风控海外商家平台。关于 TikTok 专项与业务级系统环境对齐步骤，可顺手查看 [TikTok 跨境网络与本地环境配置指南](/resources/tiktok-cross-border-network-guide/)。

## 三、自检复盘流程（改完配置后按这 3 步验收）

1. 先按规范打开 Clash / 代理开关并切换至目标节点（确定使用 `Rule` 规则且对应测试网站涵盖代理列表，或者为了纯检测该节点出口临时测试代理通道）。
2. 访问 `browserleaks.com/webrtc` 或 `ipleak.net` 并静待 5 秒让全部异步探测结束：
   - **IPv4 地址**：显示为你选中的节点落地国 IP。
   - **IPv6 地址**：不暴露你国内宽带的真实 `240x` 前缀（理想为 N/A 或受控节点出口）。
   - **WebRTC 检测区**：找不到你的家庭路由局域网私网段（`192.168.x.x`）与真实国内公网 IP。
   - **DNS Addresses**：清一色显示节点所在区域或海外标准加密 DNS，不存在国内省市运营商 DNS。
3. 验证完毕后立即关闭临时测验模式切回正常 `Rule` 分流模式，保障国内服务不走弯路。
