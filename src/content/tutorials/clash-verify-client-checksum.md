## 一、为什么不能只看「文件大小」或「杀毒软件报不报毒」？

很多用户在下载安装包时习惯用肉眼看大概几十 MB，或者丢进桌面安全卫士扫一遍没弹窗就放心双击，这在面对供应链级仿冒包时几乎没有防护力：

1. **木马体积可以控制在极小范围**：攻击者通过精细裁剪或加壳，植入一段监听剪贴板并回传数据的脚本只需要增加几十 KB，在系统资源管理器只显示「74.2 MB」这种四舍五入的估算尺寸下，肉眼根本看不出差异。
2. **杀毒软件天然对代理工具存在误报与漏报盲区**：开源代理客户端因为需要创建虚拟网卡（TUN）、修改系统代理表或打包运行环境，有时正版会被误报；反过来，带有合法壳或混淆加密的新变种木马在刚放出的头几天内往往也能绕过特征库扫描。
3. **SHA256 具备抗碰撞与雪崩效应**：哪怕安装包里只被改动了一个换行符或注入了一行恶意指令，最终算出的 64 位十六进制指纹都会面目全非。**把文件看作实名护照，SHA256 就是不可伪造的指纹页。**

## 二、第一步：找到真正可信的官方 SHA256 基准值

做对校验的前提是「对照的参考标准本身是真的」。获取权威哈希值时，遵循下面这套检查链条：

| 参考来源途径 | 可信度评估 | 获取操作重点 | 常见危险误区 |
| :--- | :--- | :--- | :--- |
| **开源项目官方 GitHub Releases 页面** | **最高（基准源头）** | 进入项目真实用户名与仓库名（如对照 [活跃客户端清单](/clash/active-clash-clients-2026/) 核验仓库拼写），展开底部的 `Assets` | 在搜索引擎点进推广域名，抄了李鬼站自己算好的假哈希 |
| **Release 附带的 `sha256sums.txt` / `.sha256` 文件** | **高（便捷批校验）** | 下载对应版本列表中的摘要文本，打开找到和你安装包文件名完全匹配的那一行 64 位字符 | 看错操作系统架构行（比如用 arm64 包比对 x64 的校验行） |
| **GitHub Actions 构建摘要（Attestation）** | **极高（开发者审计级）** | 在 Release 详情里查看是否由官方 CI 流水线直接编译生成并附带校验记录 | 忽略版本号前缀后缀差异，拿旧版校验码对比新版包 |
| **陌生群聊转发的文本或第三方网盘说明** | **极低（绝对不可信）** | 仅可作为文件传递渠道，绝对不能采信对方文字附带的校验串 | 「群主说没毒」或「博主亲测安全」替代终端命令检验 |

## 三、全平台终端一行命令实地核验演示

无需下载任何第三方「MD5/SHA 校验器」软件——Windows、macOS 和主流 Linux 发行版均已内置原生密码学散列命令，直接调用系统自带工具最干净安全。

### 1. Windows（PowerShell 原生命令）

1. 打开保存安装包的文件夹（例如「下载」目录）。
2. 在文件夹空白处按住 `Shift` 键 + 鼠标右键（Win11 可直接右键选），点击 **「在终端中打开」** 或「在此处打开 PowerShell 窗口」。
3. 输入 `Get-FileHash `（末尾带空格），打入文件名开头字母按 `Tab` 键自动补全文件名，随后加上参数执行：

```powershell
Get-FileHash .\Clash.Verge_x.x.x_x64-setup.exe -Algorithm SHA256 | Format-List
```

4. 屏幕会立即输出两行关键字段：`Algorithm : SHA256` 与 `Hash : XXXXXX...`。直接用 `Ctrl + F` 在官方 Releases 页面搜索这串 64 位字符（或前 8 位与后 8 位联合核对），**只要完全命中且与对应文件名同行匹配，即证明安装包的每个比特都未经任何修改。**

> **快捷小技巧**：想让 PowerShell 自动帮你做字符串精确比对（避免人眼看花），可以直接运行布尔判断命令（将双引号内容替换为官方给出的 64 位字符串）：
> `(Get-FileHash .\安装包文件名.exe -Algorithm SHA256).Hash -eq "官方64位哈希值"`
> 返回 `True` 为 100% 匹配，返回 `False` 立刻删文件！

### 2. macOS（系统终端 Terminal）

1. 按 `Command + 空格` 搜「终端 / Terminal」打开命令行。
2. 键入 `shasum -a 256 `（注意 `256` 后面留一个空格）。
3. 从访达（Finder）里把下载好的 `.dmg` 或 `.pkg` 文件直接用鼠标拖进黑框终端窗口里，系统会自动填充好完整绝对路径，按下回车键：

```bash
shasum -a 256 ~/Downloads/Clash.Verge_x.x.x_aarch64.dmg
```

4. 终端会在几秒内打印出一串小写 64 位哈希字符串，对比官方 `.sha256` 或页面数值即可。若要批量对比同目录下的摘要文件，可把安装包与官网下载的 `sha256sums.txt` 放在同一文件夹下执行 `shasum -a 256 -c sha256sums.txt` 查看 `OK` 状态。

### 3. Linux（Ubuntu / Debian / Arch 通用）

在对应安装包所在目录打开终端，直接运行：

```bash
sha256sum Clash.Verge_*.deb
```

或者对下载来的 `.AppImage` / `.tar.gz` 压缩包执行同样命令，确认输出的 64 位十六进制摘要与官方一致。

## 四、进阶防坑：除安装包外，安卓 APK 权限与开源脚本同样适用

- **Android APK 安装包核对**：很多用户把 GitHub 上的 `.apk` 下载到电脑或手机后直接安装。实际上手机端也可以通过文件管理器内置「属性/校验」功能查看 SHA256，或者先传到电脑运行上述 `Get-FileHash` / `shasum` 核验完再发送至手机安装。切记不要把从非官方渠道下载的 APK 直接覆盖安装到现有版本上。
- **遇到版本不一致时的红线纪律**：
  1. **哪怕只差一位字符，立即删除安装包并清空回收站**，绝对不要抱有「大概是压缩方式变了吧」的侥幸心理运行。
  2. 如果该文件你已经在未核验前运行过并导入过机场订阅，建议在重装系统或查杀清理后，立即登录机场后台执行 **「重置订阅链接（Reset Subscription）」**，并检查本地是否出现未知自启动项或浏览器恶意扩展。
  3. 下载源被阻断导致下载到一半中断的文件，计算出的 SHA256 也会不一致；此时重新完整拉取一次后再比对即可。
